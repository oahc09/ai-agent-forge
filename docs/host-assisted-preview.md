# Host-assisted preview, not product acceptance

On 2026-11-08 the user approved this specific prospective change:
continue M3 and subsequently feasible development using native agents in the current
environment as a **host-assisted preview**, while preserving original G2 and G8 as
not passed. This allows implementation and offline rehearsal out of the original
milestone order. It does not lower the original plan's acceptance thresholds.

G0/G1 retain their previously verified status. Original G2 remains blocked on actual
heterogeneous executors and OS isolation. Original G3–G7 are NOT_VERIFIED. G8 remains
NOT_VERIFIED. No real 72-hour/30-day trial, provider experiment, external repository

## Scope and trust boundary

These packages are library APIs for a trusted host and offline tests. The existing
CLI/daemon still runs only the fixed Fake worker. The new packages do not create a
new autonomous daemon, provider transport, OS boundary or GitHub write capability.
Never pass EventStore, SQLite handles, trusted callback objects, metadata admission,
review attestations or policy configuration to an untrusted candidate.

Distinct Coder/Validator/Reviewer callback roles are software contracts. Under one
OS identity they do not provide process, filesystem, credential or evaluator
isolation. Evidence digests bind bytes, not truth. Injected trusted verifiers must
actually inspect evidence; a positive label alone is not verification.

### M3 preview

`packages/autodev` and `packages/fusion` supply trusted-metadata intake, bounded DAG
scheduling and feedback, local candidate delivery/reconciliation records, and
explicitly audited routing/handoff contracts. The model/issue body never supplies
policy authority. Remote delivery is not executed by the package. Native developers
working on this repository are not counted as the product's AF-BOOTSTRAP-001 E2E.
Two real tasks with kill/recovery under isolated providers remain unverified.

### M4 preview

`packages/operations` provides:

- TriggerRouter: durable per-policy event deduplication and decisions. Observe is
  default. Auto yields ELIGIBLE only, never executes; a host runtime grant is still
  required. Metadata must come from authenticated host sources, not parsed prose.
- ProjectMemory: SQLite-backed, exact repo/branch/task/source-version capsule index
  reusing ContextBroker validation and trusted evidence verifier at ingestion and
  retrieval. TTL, archive and immutable IDs; inferred claims stay inferred. Search
  is deterministic substring ranking, not semantic retrieval. The twenty-fact test
  is a fixture-only recall measurement, not a broad retrieval quality claim.
- PilotLedger: frozen hashed protocol and ≥30 predefined task objectives/acceptance
  criteria, deduplicated claims, durable conservative budget reservations,
  approval-versus-guidance records, immutable outcomes and daily report hashes.
  Failed/blocked/timed-out/unresolved claims remain in the denominator. Outcomes are
  timestamped; late completion retains cost/denominator but cannot enter the numerator. Recorded
  guidance must set humanAssisted=true. Reservations are not refunded on failure.
  No real-provider mode exists: kind is fixture or host-assisted; claim is always
  NOT_VERIFIED even for a perfect accelerated thirty-day fixture. UTC only for now.

The ledger accepts host-observed records; it cannot independently prove costs,
independent review or wall-clock continuity. It does not schedule thirty days of
work or send notifications. Missing fully elapsed UTC-day reports are exposed in
summary(), today is not prematurely declared missing. No 72-hour soak was run.

### M5/M6 preview

`packages/radar` and `packages/evolution` are offline ingestion, provenance and
experiment metadata contracts. They do not fetch upstream code, invoke extraction
agents, run candidate code or perform production promotions. Synthetic fixture
sources are not ten observed real upstream sources. License attestations require
trusted review; no unlicensed upstream copying is authorized.

Search/controller and statistical fixture outputs do not prove real gain. Candidate
paths must stay outside policy/evaluator/kernel protections. Genuine provider-real
paired evaluation, preregistration, independent environments, hidden confirmation
sets, source inspection, ≥3 real transfers, and G8 statistical thresholds remain
unverified. Promotion/rollback proposal metadata is not a live runtime replacement.
